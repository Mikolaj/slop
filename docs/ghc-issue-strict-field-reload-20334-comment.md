# GHC issue comment: on #20334, the case binder is saved across the evaluation anyway, so the fields can be loaded from it after it

Staged and posted 2026-10-22 as [a comment](https://gitlab.haskell.org/ghc/ghc/-/work_items/20334#note_705817) on GHC [#20334](https://gitlab.haskell.org/ghc/ghc/-/work_items/20334), a follow-up to the comment posted there on 2026-10-17 ([note 704780](https://gitlab.haskell.org/ghc/ghc/-/work_items/20334#note_704780), record [ghc-issue-strict-field-loads-20334-comment.md](ghc-issue-strict-field-loads-20334-comment.md)); this file stays as the record of the comment, the text from "In the reproducer above" down being the body as drafted. It answers the objection simonpj gave on GHC [#20333](https://gitlab.haskell.org/ghc/ghc/-/work_items/20333) to holding a constructor in place of its fields across a call. The 5 instructions are the earlier comment's table, not measured again. Found again in orthotope's specialisation benchmark, where the specialised worker of Dynamic `rotate` saves a Storable vector and its three fields across a call of `length`, 8 instructions a call (three loads, a move, three stores and a stack adjustment) on the paths that never read the fields, the vector being returned whole on one of them. Neither #20334 nor #20333 had a note after 704780 when read on 2026-10-22.

In the reproducer above, `$wg` saves `v` across the evaluation of `x`, as well as the three fields of `v`, because the `x == 0` branch uses `v` itself. So the reason simonpj gave on #20333 for loading the fields eagerly (https://gitlab.haskell.org/ghc/ghc/-/work_items/20333#note_391759: "Our current policy of loading eagerly, and spilling, has the advantage of only saving things that are definitely alive") does not apply here: the saved `v` keeps its fields alive in any case.

When the case binder is saved across a call or an evaluation, the code generator could save only the case binder and load the fields from it after the call, where they are used, as the lazy variant loads them in the branch. In the table above, that is the difference between the two variants, 5 instructions an iteration.
