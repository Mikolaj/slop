# Claude Code issue comment: the classic renderer's scrollback loss on 2.1.304 and VTE 0.76, how its debug log shows the cuts, and two renderer switches that do not help

Posted 2026-10-20 as [a comment](https://github.com/anthropics/claude-code/issues/98019#issuecomment-6292216326) on anthropics/claude-code [#98019](https://github.com/anthropics/claude-code/issues/98019) ("Classic renderer drops or overwrites output when anything above the visible window changes height (verbose makes it frequent)"); this file stays as the record of the comment, the text from "Still present in 2.1.304" down being the body staged for it, one paragraph per line for GitHub. Read on 2026-10-20: the issue's description and its three comments, of 2026-10-08, 2026-10-14 and 2026-10-15. Measured the same day with Claude Code 2.1.304 against a local mock of the Messages API, in a headless VTE 0.76 at 238x59; the scripts and captures were scratch and are not kept.

Still present in 2.1.304 (built 2026-10-19), and seen on Linux in GNOME Terminal 3.52.0 (VTE 0.76.0) at 238x59, with the classic renderer selected by `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`. The setup runs five PreToolUse hooks on every Bash call and a Stop hook, so by the cap described in the comment of 2026-10-14 the cuts come often, and so do the gaps in the scrollback.

Reproduced deterministically by replaying a recorded long session (mostly Bash calls, with thinking and narration blocks, and the same hooks) through a local mock of the Messages API, with Claude Code running inside a headless VTE 0.76 at 238x59. Three runs lost the same rows: the last item of one reply and the blank line before it, three rows.

Three additions:

- **The debug log can show a cut.** With `CLAUDE_CODE_DEBUG_REPAINTS=1` and `--debug`, the renderer logged `[REPAINT] full reset` warnings of reason `offscreen`, triggered near the top of the frame (rows 6 and 7 here, just below the startup banner), whose `prev` and `next` lines are two consecutive transcript entries, such as one Bash command's line and the next one's. The three rows above vanished in a write that erased the screen with `ESC[H`, then `ESC[2K ESC[1B` 59 times, then `ESC[H`, 40 ms before such a warning was logged. In the same update a Bash call's output below grew by three rows, as point 5 of the comment of 2026-10-14 describes.
- **`CLAUDE_CODE_DISABLE_VIRTUAL_SCROLL=1` changes nothing**: the same rows are lost, and resets of the same kind are logged at the same frame rows.
- **The scroll-region renderer is no workaround on VTE.** With `CLAUDE_CODE_DECSTBM=1` and the same replay, the terminal ended with 88 lines in its whole buffer, where the classic renderer leaves about 1100, and none of the eight long replies checked came out whole: four never appeared and four lost parts. It wrote 107 KB where the classic renderer wrote 821 KB, with no erase-display sequence, so most of the output was apparently never written. VTE does keep lines scrolled out of a scroll region that starts at row 1 (checked directly), so the terminal is not discarding them.

**Reproducing it without an account, in under two minutes.** What worked here:

- **A local server stands in for the API.** Set `ANTHROPIC_BASE_URL=http://127.0.0.1:PORT` with any `ANTHROPIC_API_KEY`, and have the server answer `POST /v1/messages` with scripted SSE streams. It picks reply k for a request carrying k assistant messages, so the script replays in order, and gives every other request a one-word reply.
- **The script.** Three stretches of one-sentence text replies, 100, 60 and 60 of them, each with a Bash call `seq 1 n`, and after each stretch a long Markdown reply (nested numbered lists) that ends the turn; a typed prompt starts each turn. At 238x59 this left 3 gaps without hooks and 4 with five PreToolUse hooks on Bash and a Stop hook, each a short `sleep` (86 and 106 of 5672 numbered words lost, 9 and 18 full resets), the first about 70 replies in. A variant whose replies carry an empty thinking block and a narration block in place of the text left 5 to 11 gaps per run, at 238x59 and at 80x24.
- **Isolation.** Use a fresh `CLAUDE_CONFIG_DIR` and `HOME`. Their `.claude.json` sets `hasCompletedOnboarding`, the work directory's `hasTrustDialogAccepted`, and the key's last 20 characters under `customApiKeyResponses.approved`; their settings allow `Bash` and set `permissions.disableAutoMode` to `"disable"`, since auto mode's classifier asks the mock, gets no verdict, and can block commands.
- **Numbered prose.** Numbered words in the scripted text (`q000001`, `q000002`, ...) turn every lost row into a countable gap in the final scrollback.
- **Locating the reset.** Record with `script -q -f --log-out cap.out --log-timing cap.tm -c claude`, then replay `cap.out` into an emulator one write at a time: the write after which a numbered word disappears is the full reset. VTE has not finished parsing when `feed` returns, so wait until its cursor and buffer stop changing before reading it back.
- **Length matters.** Short sessions showed nothing here: three long replies, or `/context` typed seven times, lost no row.
