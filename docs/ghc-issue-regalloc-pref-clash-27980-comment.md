# GHC issue comment: !16673, the fix for #27800, leaves #27980's and #27981's reproducers unchanged

Staged and posted 2026-10-20 as [a comment](https://gitlab.haskell.org/ghc/ghc/-/work_items/27980#note_705394) on GHC [#27980](https://gitlab.haskell.org/ghc/ghc/-/work_items/27980), filed from `docs/ghc-issue-regalloc-pref-clash.md` and closed on 2026-10-20 by AndreasK as a duplicate of GHC [#27800](https://gitlab.haskell.org/ghc/ghc/-/work_items/27800); this file stays as the record of the comment, the text from "I checked" down being the body as drafted. It answers the last note there, which says !16673 probably does not change this case, unverified. Verified on 2026-10-20 with quick-flavour builds of `merged-mrs` at 12bd4c0c7a (master 3d326d7d28 with MRs, none of them touching the register allocator) and of the same with GHC [!16673](https://gitlab.haskell.org/ghc/ghc/-/merge_requests/16673)'s 0940911d2a cherry-picked cleanly, on the reproducers of #27980 and of GHC [#27981](https://gitlab.haskell.org/ghc/ghc/-/work_items/27981) as their documents show them. Found while checking whether !16673 removes a register swap through a stack slot in a loop of orthotope's `specialisation` benchmark (a4e014a7): it does not. That loop is left out of the body: the `disp` reproducer of #27980 shows the same swap, and runs.

I checked the question in my last note. With !16673 (0940911d2a, cherry-picked cleanly onto master 3d326d7d28 with some unrelated MRs), both reproducers in the description compile to the same assembly as without it (`-O -ddump-asm`, time stamps aside): `pref.cmm` still has the fixup block `.Ln4: movq %rax,%rcx` on the loop's path from its return continuation, and the `disp` variant of `Lib.hs` still swaps `%rax` and `%rdx` through the C stack in `.Ln5`, every iteration. The same holds for the reproducer of #27981 (`.Ln8: movq %rcx,%rbx; movq %rdx,%rcx`). The patch was active in that build: !16673's own `T27800.cmm` goes from 4 stack-slot accesses and 2 fixup blocks to 2 and 1. So !16673 does not fix this issue.
